# failure-latch-check

> **状态**：已实例化为草稿。存在 2026-09-14 引导演练的事后记录（见 [notes/governance-line/2026-09-14-judgment-card-drill-record.md](../../../notes/governance-line/2026-09-14-judgment-card-drill-record.md)），证据不足以验收运行有效性；自然触发及独立执行约束未验证。

## 问题类型
检测到重复失败时，判断是否应熔断、收敛或升级，防止盲冲。

## 适用条件
- 同一工具或同一目标连续失败 2 次
- 同一类操作在短周期内多次失败
- 失败后 agent 试图自动扩大范围（更多权限/更多工具/更多上下文）
- 首次失败不适用本卡（首次失败走 FAILURE-PROTOCOL.md 报告流程）

## 必要前提
- 已记录失败次数和失败原因
- 已确认是否为同类失败（工具/目标/错误类型）
- 已检查是否有人类 override 授权

## 判断原则
1. **同类失败 2 次后禁止第 3 次盲冲**：必须停止、排查、升级，不得继续硬试。
2. **失败后不得自动扩大范围**：不得为"找原因"而扩大历史读取、权限或外部调用范围。
3. **先收敛再决定**：默认动作是收敛（停止继续展开），收敛后再决定是否升级或写回。
4. **参数/schema 错误必须回验**：因参数错误导致的失败，必须先回验 schema，不得直接重试。
5. **人类 override 需显式标记**：若人类明确授权继续，标记 `human_override` 后继续，否则熔断。

> 注：本卡约束的是"未经排查的盲目重试"与"失败后自动扩大范围"。不禁止经过最小排查、明确记录原因的重试；不扩大人类授权可覆盖的权限范围。

## 常见陷阱
- 陷阱 1：将失败包装为 "partially completed" 后继续扩大范围。
- 陷阱 2：换另一个工具尝试同一目标，绕过"同类失败"计数。
- 陷阱 3：将 "排查原因" 作为扩大上下文范围的借口。
- 陷阱 4：未记录失败次数，导致隐性连续失败。

## 稳定表达
```
失败计数：[n] 次同类失败
失败工具/目标：[具体]
失败原因：[已分类]
熔断决策：[converge / escalate / human_override / not_yet]
下一步：[具体动作]
```
