# effect-verification-check

> **状态**：已实例化为草稿。存在 2026-09-14 引导演练的事后记录（见 [notes/governance-line/2026-09-14-judgment-card-drill-record.md](../../../notes/governance-line/2026-09-14-judgment-card-drill-record.md)），证据不足以验收运行有效性；自然触发及独立执行约束未验证。

## 问题类型
agent 声称某项规则、协议、运行时约束或文件变更已实施/已加载/已完成时，验证该声称是否成立。

## 适用条件
- agent 报告某文件已写入
- agent 报告某规则已加载
- agent 报告某协议已实施
- agent 报告某约束已生效
- 仅涉及内部推理而无外部状态变更时，本卡不适用

## 判断分支

### 分支一：核查匹配
- 独立读回或状态检查与声称一致
- 可报告 completed_and_verified，并标注验证等级

### 分支二：核查不匹配
- 独立读回与声称不符
- 不得报告完成；报告差异并停止盲目重试
- 在既有授权范围内可进行必要排查或修正；超出权限或触及既有升级条件时，再请求人类决定

> 注：核查匹配仅支持被核查的具体声称。文件读回成功不证明规则已加载或已生效。

### 分支三：核查不可得
- 独立核查因系统级错误、权限、路径不可达等原因无法完成
- 保持 unverified，不报告完成
- 涉及可能重复产生副作用的操作（写入、外部调用等），不得盲目重试
- 报告人类：目标状态无法确认

## 判断原则
1. **文件已写 ≠ 规则已加载**：文件存在最多证明 L0 Documented，必须验证 runtime 是否读取。
2. **规则已读 ≠ 规则已生效**：必须经行为验证（探针或负向测试）才可声称 L4 Verified。
3. **本地成功 ≠ 远端成功**：内部状态变更与外部状态变更必须分别验证。
4. **调用成功 ≠ 目标达成**：工具返回成功不代表预期副作用已发生。
5. **独立核查优先**：验证必须依赖与执行动作独立的读回或状态检查，不得仅依赖执行工具的返回值。

## 常见陷阱
- 陷阱 1：以 exec 退出码 0 作为完成证据，未独立读回目标状态。
- 陷阱 2：以文件修改时间戳作为写入证据，未核对内容。
- 陷阱 3：以配置文件中存在某条目作为已生效证据，未验证 runtime 是否加载。
- 陷阱 4：将 "git add" 等同于 "已提交"，将 "commit" 等同于 "已推送"。
- 陷阱 5：核查不可得时重试，造成重复副作用（如重复写入）。

## 稳定表达
```
声称：[具体对象] 已 [声称性质]
验证方法：[独立读回/状态检查/探针测试]
验证结果：[匹配/不匹配/无法确认]
任务状态：[completed_and_verified / unverified / blocked]
```
